## 1. 概要

登録しておいた「やりたいこと」から、その日に取り組むものをランダムに 1 件選ぶ Web アプリ。完了した項目は履歴として確認でき、誤操作は取り消せる。

要件（[referende.md](referende.md)）に加えて、以下を実装済み:

- **グループ**: 項目を「勉強」「遊び」などのグループに分けられる。グループの追加・名前変更・削除ができる。
- **選出対象の指定**: すべて / 特定グループ / おまかせ（グループも抽選）から選べる。
- **使い方チュートリアル**: ヘッダーのヘルプボタンから開くモーダル。
- **配色テーマ**: 暗いネイビー（既定）と白背景の 2 種類から選べる。

## 2. 技術構成

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| 形態 | SPA（ブラウザのみで動作） | サーバー・外部アカウント不要の最小構成 |
| UI | React 19 + TypeScript | 既存リポジトリの構成に従う |
| ビルド | Vite | 同上 |
| データ保存 | `localStorage` | 再読み込み後もデータを保持でき、サーバー不要 |
| テスト | `node:test`（`npm test`） | 追加依存なしでドメインロジックを検証できる |
| Lint | ESLint（typescript-eslint, react-hooks） | |

ルーティングライブラリは使わず、`App` が表示中の画面を state で切り替える（URL は変わらない）。

### コマンド（`frontend/` で実行）

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー起動 |
| `npm run build` | 型チェック + 本番ビルド |
| `npm run lint` | Lint |
| `npm test` | ドメインロジックのテスト |
| `npm run capture:tutorial` | チュートリアル用の画面画像を撮り直す（`npm run dev` 起動中に実行） |

### レイヤーの責務

```
pages / components  …表示とユーザー操作。ロジックは持たず props のコールバックを呼ぶ
        ↑ props
App.tsx             …hooks から状態を受け取り、画面に配る。選出結果など一時的な状態を保持
        ↑
hooks               …lib の純粋関数を setState に包み、localStorage に保存する
        ↑
lib                 …ドメインロジック（純粋関数）。React にも localStorage にも依存しない
```

ロジックは `lib/` に集め、`node:test` で直接テストできるようにしている。

## 4. データ設計

### 4.1 Item（やりたいこと）

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | string | 一意な ID（`crypto.randomUUID`、使えない環境では時刻 + 乱数） |
| `text` | string | 内容（前後の空白を除去済み） |
| `groupId` | string | 所属グループの ID |
| `status` | `"todo"` \| `"done"` | 未完了 / 完了 |
| `createdAt` | string | 登録日時（ISO 8601） |
| `completedAt` | string \| null | 完了日時（ISO 8601）。未完了なら `null` |

### 4.2 Group（グループ）

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | string | 一意な ID。初期グループは固定 ID（`study` / `play`） |
| `name` | string | グループ名（前後の空白を除去、重複不可） |

初期グループ: `勉強`（`study`）、`遊び`（`play`）。

### 4.3 保存

| キー | 内容 |
| --- | --- |
| `yaritaikoto.items.v1` | `Item[]` の JSON |
| `yaritaikoto.groups.v1` | `Group[]` の JSON |
| `yaritaikoto.theme.v1` | 配色テーマ（`"dark"` / `"light"` の JSON 文字列） |
| `yaritaikoto.tutorialSeen.v1` | チュートリアル既読フラグ（`"1"`） |

- state が変わるたびに JSON で保存する。保存に失敗する環境（プライベートモード等）ではメモリ上のみで動作する。
- 別タブで変更されたら `storage` イベントで反映する。
- 配色テーマの不正値・未保存は `dark`。
- 選出結果・選出対象・表示中の画面は**保存しない**（再読み込みで初期化）。

### 4.4 読み込み時の扱い

- 項目: 壊れた JSON・配列以外は空として扱う。不正な要素だけ捨て、正常な要素は残す。
- 項目: `groupId` のない旧データは `play`（遊び）に移行する。
- グループ: 未保存・壊れたデータ・0 件のときは初期グループを使う。
- 整合性補正（`reconcileItems`）: 存在しないグループに属する**未完了**項目は先頭のグループに寄せる。**完了**項目は元の `groupId` を保持する（履歴ではグループ名を表示しない）。

### 4.5 状態遷移

```
       登録                やった
 (なし) ───▶ todo ──────────────▶ done
              ▲  ◀──────────────  │
              │  やっぱやってなかった
              │                  （completedAt をクリア）
            削除（todo のみ）
```

- 完了時に `completedAt` に現在時刻を記録する。
- 削除は未完了項目のみ。完了履歴の削除機能はない（要件どおり）。

## 5. 画面設計

全画面共通: ヘッダーにアプリ名（「きょう、なにする？」）・テーマ切替ボタン・ヘルプボタン、タブ（決定 / やりたいこと / やったこと）。タブには未完了・完了の件数バッジを表示する。

### A. やりたいこと決定画面（`DecidePage`）

- 選出対象をチップで選ぶ: **すべて** / **各グループ**（件数付き） / **おまかせ**。
- 「選出」で 1 件選び、結果をグループ名とあわせて表示する。選出後はボタンが「再選出」になる。
- 選出しても完了にはしない。結果の下に、一覧で「やった」にするよう案内するボタンを出す。
- 未完了が 0 件のときは、登録を促す案内と一覧画面へのボタンを表示する。
- 選んだグループに未完了がないときは、選出ボタンを無効にして案内を出す。
- 再選出で同じ項目が出ても分かるよう、選出のたびに結果のアニメーションを再生する。

### B. やりたいこと一覧画面（`TodoListPage`）

- グループを選んで内容を入力し「登録」。空・空白のみの場合は登録せずエラーを表示する。
- 未完了項目をグループごとに表示する。選出中の項目には「今日やること」タグを付ける。
- 各項目: 「やった」（完了）、「削除」（確認を挟む 2 段階操作）、グループ変更（グループが 2 つ以上のとき）。
- グループの編集（一覧上でその場で行う）:
  - 各グループ見出し（`GroupHeading`）の鉛筆アイコンで名前変更、ゴミ箱アイコンで削除。Esc・キャンセルで中止。
  - 一覧末尾の「グループを追加」（`AddGroupForm`）で追加。
  - 追加・名前変更: 空・重複は不可。
  - 削除: グループが 1 つしかない場合、または未完了項目が残っている場合は不可（理由を表示）。確認を挟む。

### プルダウン（`Select`）

ブラウザ標準の `<select>` はメニューの見た目を変えられないため、独自のプルダウンにしている。登録フォームのグループ選択（`field`）と、各項目のグループ変更（`compact`）で使う。

- WAI-ARIA の select-only combobox パターン。フォーカスはボタンに残し、`aria-activedescendant` で操作中の項目を示す。
- キーボード: ↑↓ / Home / End で移動、Enter・Space で開く・決定、Esc で閉じる、Tab で決定して次へ、文字キーで頭文字の項目へ移動。
- 外側のクリック・タップで閉じる。
- メニューは `position: fixed` で表示する（一覧カードの `overflow: hidden` で切れないように）。下に入らなければ上に開き、スクロール・リサイズに追従する。

### C. やったこと一覧画面（`DoneListPage`）

- 完了項目を完了日時の新しい順に表示する（グループ名・完了日時付き）。
- 「やっぱやってなかった」で未完了に戻す。
- 0 件のときは案内を表示する。

### 配色テーマ（`useTheme`）

- ヘッダーの太陽／月アイコンで切り替える（表示中と逆のテーマのアイコンを出す）。
- `<html data-theme="dark|light">` を切り替え、`index.css` の CSS 変数を差し替える。コンポーネント側は色を直接書かず、変数だけを使う。
  - 暗いネイビー（既定）: ネイビー背景 × 白文字・白の図形、選択状態は薄い青。
  - 白背景: 同じネイビー・薄い青を使い、ダークで白だった図形（主ボタン・タグ等）をネイビーに反転する。カードは薄い青みのグレー面＋枠線で背景と区別する。
- 再読み込み時のちらつきを防ぐため、`index.html` のインラインスクリプトで描画前に `data-theme` を反映する（キー・形式は `useTheme` と同じ）。
- チュートリアルの画面画像もテーマごとに用意し、表示中のテーマに合わせて切り替える。

### 使い方チュートリアル（`Tutorial`）

- 初回起動時は自動で開き、閉じたら既読を保存する（`useTutorial`）。以降はヘッダーのヘルプボタンから開く（決定画面の説明カードにはリンクを置かない。重複を避けるため）。
- 4 ステップ（登録 → 選出 → やった → 振り返り）を「戻る / 次へ」で切り替える。
- 各ステップに実際の画面のスクリーンショットを表示し、操作する箇所を薄い青の枠で示す。
  - 画像は `src/assets/tutorial/*.webp`。`scripts/capture-tutorial.mjs` が Chrome をヘッドレスで起動し（Chrome DevTools Protocol を Node 標準の WebSocket で操作、追加依存なし）、サンプルデータを入れた画面を撮影して生成する。暗いネイビー版は `stepN-*.webp`、白背景版は `stepN-*-light.webp` として両テーマ分を撮る。
  - **画面の見た目を変えたら `npm run capture:tutorial` で撮り直す。**
  - 画像の縦横比はステップごとに違うが、表示枠の高さは固定（`object-fit: contain`）にして、ステップを切り替えてもボタン位置が動かないようにしている。
- ネイティブの `<dialog>` を `showModal()` で開く。Esc・背景クリック・閉じるボタンで閉じる。
- 開いている間だけマウントする（開くたびに 1 ステップ目から表示）。

## 6. 選出ロジック（`lib/items.ts`）

| 対象 | 候補 | 確率 |
| --- | --- | --- |
| すべて | 全グループの未完了項目 | 各項目が等確率 |
| グループ | そのグループの未完了項目 | 各項目が等確率 |
| おまかせ | 未完了項目があるグループを等確率で選び、その中の項目を等確率で選ぶ | グループが等確率（項目数に依存しない） |

- 等確率の選択は `list[Math.floor(random() * list.length)]`。乱数関数は引数で差し替えられ、テストで値を固定できる。
- 再選出で直前と同じ項目が出ることは許容する（要件どおり）。
- 選出結果は ID で保持し、その項目が完了・削除されたら選出結果を消す。
- 選択中のグループが削除されたら、対象を「すべて」に戻す。

## 7. 要件との対応・仮定

| 未決事項（要件 6 章） | 本実装での扱い |
| --- | --- |
| 対象プラットフォーム | Web（スマホ幅でも使えるレイアウト） |
| アプリ名 | 「きょう、なにする？」 |
| データ保存・同期 | `localStorage`。端末間の同期はしない |
| 重複登録 | 項目は許可（グループ名は重複不可） |
| 完了項目の保持期間 | 無期限 |
| 選出履歴 | 記録しない |
| ログイン・共有・通知・期限など | なし |

## 8. テスト

`lib/items.test.ts` で、受け入れ条件（要件 5 章）のうちロジックで確認できるものと、グループ機能を検証している。

- 空入力は登録されない / 登録すると未完了一覧に出る / ID が一意
- 選出は未完了からのみ・等確率・選出しても状態は変わらない・0 件なら `null`
- やった → 完了日時の記録 / やっぱやってなかった → 完了日時のクリア
- 削除は未完了のみ / 完了一覧は新しい順
- 保存データの読み込み（壊れたデータ・旧データの移行）
- グループの入力チェック・追加・名前変更・削除・項目の移動・整合性補正
- グループ指定の選出 / おまかせの確率

画面の動作（画面遷移・表示）は自動テストがなく、`npm run dev` での手動確認による。

## 9. セキュリティ上の考慮

- サーバー・外部通信なし。データは端末の `localStorage` にのみ保存する（第三者には送信されない）。
- ユーザー入力は React の通常の描画（テキストノード）で表示し、`dangerouslySetInnerHTML`・`eval` などは使わない（HTML を入力しても文字列として表示される）。
- `localStorage` の内容は信頼せず、読み込み時に型を検査して不正な要素は捨てる（4.4）。
